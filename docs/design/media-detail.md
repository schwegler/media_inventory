# Compact media metadata and public shelf discovery

Design checkpoint before implementation — 26 October 2026; base 9e194e21.

The overview retains cover, title, synopsis, key facts, rating and tracking jump. The existing document navigation (Overview / My Library / Details / Episodes or Issues / Community / Comments) remains document navigation. Quick actions, related reading, tracks, series entries and private game tracking stay independent.

Only the detailed metadata block becomes compact. Its heading is Details, followed by a thin horizontally scrollable tab row, an understated Show all control and a two-column definition list. Current surface, border, accent, text and typography tokens apply in both themes. Tabs have 44px minimum targets and a visible active underline and focus outline. At narrow widths the tab row scrolls independently, facts stack and long values wrap. No fixed height truncates credits or descriptions.

Categories use available content: Details for technical/publication/provider facts, Cast only for screen actor credits, Crew for screen creators and Creators for other media, Genres or Features for taxonomy/game features. Empty categories disappear. One category needs no tabs. Release year remains a fact; no invented Releases category. Linked metadata entities and category links remain links. Provider synopsis duplicating the visible synopsis is removed; other descriptions remain. Header facts remain useful while duplicate detailed facts and structured credits merge by role.

Without JavaScript all categories are visible with normal fragment links and headings. Enhancement adds ARIA tablist/tab/tabpanel, roving focus, automatic selection on arrow/Home/End, and a Show all escape. Category fragments select their panels on initial load and history changes without intercepting top-level navigation. Searchable hidden-until-found panels reveal through beforematch; browsers without that support retain the expanded document presentation. Expanded mode restores all content to the accessibility tree. Turbo snapshots retain the selected/expanded island layout; reconnect restores its semantics without changing document height before native fragment scrolling. Fresh no-JavaScript responses remain fully expanded.

Below community content, On public shelves uses compact cover-strip rows: bounded catalog covers left, shelf title, creator and stored pick count right. No engagement claims. Up to six rows; deterministic recency with a stable tie break. Omit when empty. Discovery consumes the shelf task's shared public contract and respects its publication eligibility gates. Named collections require their own explicitly published current preview; an account-level or stale collection preview cannot qualify them. No library, review or tracking data enters these rows.

Verification targets: desktop/mobile light/dark screenshots, 320px reflow (200% at 640px), long/missing metadata, all six catalog types, linked credits and tracks/episodes/issues, keyboard, fragment history, find-in-page, no JavaScript and owner/visitor privacy. Query cost must remain bounded with batched preview resolution.

Implementation notes: reference MP4 was materialized locally through the current Library helper, then decoded as media with FFmpeg; 0/5-second frames confirm the independent metadata island and 10/15-second frames show compact cover-strip list rows. No attachment code was executed. The shelf service is shared with the separate shelves draft: original shared commits b0df5b69 and 9beea6f3 are included; their local hashes change on rebase. Publication-safe named eligibility and bounded metadata loading are shared follow-ups 8579aafd, 69c2e690 and ea424b07. This draft changes no review presentation blocks; the separate review draft owns those.

Final discovery bound: typed JSON membership checks examine the 500 most recently updated publication candidates in total, returning six matches here (service maximum twelve). Up to five catalog covers per row resolve in batches by media type. Older matching shelves can be absent, so this is incomplete discovery; the UI explicitly says older matches may be missing. Favorite shelves retain the existing homepage publication gates. Named collections additionally require a collection-specific preview with the exact current signature, preventing a generic account preview or stale unpublished edit from exposing a collection through discovery. No LibraryItem or review data participates in membership or cards.

History uses native fragment URLs while retaining Turbo restoration identifiers. Selected/expanded metadata presentation is retained in history and a bounded transient cache of twenty paths; it stores no catalog content or viewer tracking state. Caching never expands the live metadata island, preserving anchor geometry. Focused regressions keep the existing strict header/anchor assertions and cover direct URLs, reload, backward/forward navigation, Turbo back, searchable panels and expanded-state restoration.

Measured lookup budget: five SQL queries for six same-type favorite rows; named publication checks use one distinct tuple query bounded by the matched candidate count, with no preview blob/history preload. Small cover previews request the existing 180px rendition and decode lazily.

Searchability regression: the global `[hidden] { display:none!important }` reset is overridden only for metadata panels in the `until-found` state, retaining searchable content-visibility boxes. Browser tests check computed display/content visibility, Chrome text-search discovery and the beforematch reveal action. A native Chrome find-menu attempt was blocked by an unrelated pre-existing file dialog; that dialog was left untouched, and the isolated verification tab/server were closed. Native find-menu interaction and assistive-technology speech remain manual verification limits.

Both JSON paths have a 500-record lookback: the combined recent favorite/named candidate ID window precedes typed-pick JSON inspection, and the newest preview attachment ID window across matched named curators precedes exact category/signature JSON inspection. Unpublished or stale named candidates can crowd the first window, and older valid previews can fall outside the second. These create additional false negatives, never broader publication eligibility. Discovery is intentionally incomplete; all returned named shelves still require a verified current collection-specific signature.
