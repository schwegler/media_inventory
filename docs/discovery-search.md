# Public catalog discovery (P0)

Ordinary search still returns the real shared Trove catalog, including contributor and imported child-title matches. It now names that scope **In Trove** and exposes **Available to import** in the same journey. All-media searches show explicit media choices; selecting one type starts its existing bounded, cached asynchronous provider search. There is no automatic fan-out across all six types. The public homepage now has an immediate search form, explains all six formats and coverage, and shows populated real favorite shelves only for confirmed members with usernames who have published a shelf share preview. No featured records or popularity claims are invented.

Provider coverage is unchanged: music discovery searches albums, not an external song catalog or complete discography. iTunes album queries use `entity=album`, US, limit 5; combined provider candidates cap at 20. **Find more matches** refines the retained query rather than claiming unsupported pagination. Search outcomes distinguish pending, complete zero, partial/unavailable and queue failure. Existing array-based autocomplete callers remain compatible; discovery opts into an envelope with source outcomes. Results with a known provider identity link to the existing catalog title; signed-in personal membership labels use private/no-store responses and never include reviews.

A CSRF-protected selection POST validates the existing type-bound signed import token and stores the bounded intent in the shared cache. The encrypted session carries only a random intent handle. Login/signup session rotation retains that handle for a previously anonymous visitor; logout and explicit successful save clear it. Repeated discovery confirmations never overwrite a title’s existing personal tracking or private review. Authentication never imports automatically. A resumed candidate enters the existing selected-source preview and explicit confirmation, preserving metadata protections, personal tracking options and existing game identity rules. Auth pages disable Turbo snapshots to avoid replacing typed credentials during a cached-preview refresh. Discovery confirmation Back, Close and Escape return to the original query/type; ordinary Add modals retain their prior behavior. Expired signed selections return to the retained query with a reselect message. Intent storage expires after an hour; source selections still expire after thirty minutes.

Signed inventory imports now share the existing shelf provider-identity mutex through the whole catalog/library save; local selections lock their existing catalog row. No catalog uniqueness migration, existing duplicate cleanup or manual/admin writer change is included. Legacy writers outside these locks can still race; no catalog-wide uniqueness guarantee is asserted. The original shelf importer still creates catalog records only, without personal library additions.

Synthetic regression evidence covers Madonna, Buckethead and Charli xcx queries; album limits, cache reuse/refinement, unavailable/zero/partial results; local identity and private membership; tampered/cross-type/expired selection; failed login, signup switching, interrupted sign-in; explicit/repeated save; keyboard selection; back/forward; mobile widths and 200% zoom. All artist/provider responses are mocked fixtures, not live availability claims. CI checks the exact PR head, runs the full non-browser suite and its configured browser suite, and retains responsive screenshots in `trove-responsive-ui`. New screenshots have `discovery-synthetic-` prefixes.

Scope deliberately excludes broad onboarding, recommendations, new providers, production enrichment/backfill and deployment. No production records, settings, credentials or user libraries were accessed or changed. Existing stale regression expectations were aligned with current master behavior: the signed import confirmation says **Confirm and save**, and the friend-feed fixture must actually follow its friend.

## Signed-out homepage visual refinement

The homepage now leads with a short collection proposition and one visible search field. Real attached catalog covers form the hero; actual public shelf picks appear in cover-led rows. Coverage/import limits and the existing community feed use native disclosure controls instead of instruction-heavy panels. The mascot and blog remain a small part of the composition. Empty artwork/shelf states remain honest and do not manufacture sample records.

Cover selection is read-only: real public picks first, then a bounded sample from existing locally stored catalog artwork (six records per supported type, six visible covers total). No provider search, image download, import or ownership write occurs to compose the hero. Public shelf items are loaded once and reused. Synthetic visual tests attach genuine provider cover samples with provenance in `spec/fixtures/files/discovery_covers`; these are test-only assets, never seeded production content. Phone, desktop, dark mode, zoom, image loading, query retention, keyboard navigation and disclosure tests accompany the existing discovery and authentication regressions.
